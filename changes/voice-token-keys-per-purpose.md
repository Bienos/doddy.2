Voice token server: a key of its own for each job, a key id in everything signed or sealed, and an optional previous key for rotation (step 2 of `docs/decisions/2026-11-12-account-and-device-tokens.md`, part b). Nobody is signed out and no setting has to be set at deploy; two optional settings exist for a later rotation: `DODDY_SESSION_SIGNING_KEY_PREVIOUS` (checking and opening only, never signing or sealing) and `DODDY_IDENTIFIER_KEY`. Steps and rollback: `server/voice-token/README.md`, "Keys" and "Rotating the signing key".
Where the server signs, seals or derives something from `DODDY_SESSION_SIGNING_KEY` (`src/voice-auth.js`, `src/conversations.js`, new `src/keys.js`):
- Access tokens (HS256, 10 minutes): now the key derived for `doddy/voice/access-token/v1`, with `kid` in the header. Tokens without `kid` (made before) are still checked with the key itself.
- Apple's refresh token, sealed (AES-256-GCM): now the key derived for `doddy/voice/apple-token-seal/v1`, kept as `v2.<key id>.<value>`. Values without the prefix (made before) still open.
- Apple pseudonym (`apple-sub:`), conversation `recordKey` and `userId` (`voice-conversations:`, `voice-user:`) and the rate-limit buckets (`client:`, `delete-conversations:`, `apple-link:`): unchanged, byte for byte, on the identifier key (`DODDY_IDENTIFIER_KEY` when set, otherwise the signing key as before). Tests hold values recorded from the code before this change.
- Not key uses, left as they are: refresh tokens (random, kept as SHA-256 hashes, so they never depended on a key), the nonce hash, the `CRON_SECRET` comparison, Supabase account tokens (the project's published keys), Apple's client secret (Apple's own key).
Ran: `node --test test/*.test.js` in `server/voice-token` (145 pass: the 114 earlier tests unchanged and 31 new, including a real local Redis), `scripts/ci.sh --only checks`, `scripts/ci.sh --only node` (web end-to-end skipped: no Chromium here). Not run: anything against Vercel or the live Upstash store; nothing deployed.
Merging ships it: Vercel builds `doddy-voice-token` from `main`. Owner steps: none. A rotation (README) is optional and the owner's to run; a rollback of the code leaves tokens made before this valid, and the new-format ones are refused by the earlier code (access tokens for up to 10 minutes, sealed Apple tokens until their holder signs in with Apple again).
