Voice token server: a small daily pool for new accounts, a fair share per account inside the hourly budget, and a daily ceiling for the whole service (items 1 and 2 of `docs/decisions/2026-11-12-voice-token-fair-share.md`; items 3 and 4, web sign-up and the web chat pool, are a separate change in `backend/`). All of it is in the one Redis script behind `hitLimits`, so a refused request still uses no budget and there is no extra round trip (ADR-671).
- **New accounts:** for its first 7 days an account has 10 tokens a day of its own and draws from a pool of 100 a day shared by all new accounts. The server keeps one key per account holding only the UTC day of its first token. Accounts whose first token comes in the first 7 days after this code starts running count as established, using a start day stored once in Redis (not a deploy-time setting), so today's testers keep their limits. A reset store counts everyone as established for 7 days rather than as new.
- **Fair share and ceiling:** once half of the hour's 100 tokens are used, an account that already had 10 that hour waits for the next hour (log `limit: fair_share`); 600 a day is the ceiling for the whole service (`DODDY_GLOBAL_TOKENS_PER_DAY`). The app sees the same `rate_limited` with `Retry-After`; its wording is unchanged.
- **What it means for people:** a new person gets fewer voice conversations in their first week, and a heavy user is refused sooner while the service is busy.
- Six optional settings, all with the defaults above (`server/voice-token/README.md`, "How the limits fit together"); their names are recorded in `secrets/manifest.json` as plain numbers (no secret).
Ran: `node --test test/*.test.js` in `server/voice-token` (the new rules run against an in-memory model and against the real script on a local redis-server 7.0.15), `scripts/ci.sh --only node`, `scripts/ci.sh --only checks`. Not run: anything against Vercel or the live Upstash store; nothing deployed; the iPhone app is untouched.
Merging ships it: Vercel builds `doddy-voice-token` from `main`. **No setting has to be set; the defaults apply at once.** Rollback: revert the pull request; the earlier code ignores the extra Redis keys (per-account first-seen days expire after 180 days without a token, counters after a day). To start the first-week grace again on a later redeploy, delete the one key `doddy:voice:v1:fair-share-started` first (README).
