Voice server: deleting an account also deletes its voice conversations at ElevenLabs (decision `2026-11-12-voice-conversations-per-account`). The server records which conversation belongs to which account when it issues a token (refusing the token if it can't), adds the account's keyed `userId` to the token answer, and has a new `delete-conversations` action (and the older voice accounts' `delete-account`) that deletes each conversation and counts it only after a read-back answers 404. What isn't confirmed stays owed and a daily Vercel cron retries it.
Ran: `npm test --prefix server/voice-token`; `node tools/secrets/sync.mjs check`; `scripts/ci.sh --only checks`. Not run: anything against the live ElevenLabs or Vercel. ElevenLabs' public reference says the token answer carries `conversation_id`; the live service wasn't asked.
Merging deploys `server/voice-token` to Vercel production (new function `/api/voice-cron`, `maxDuration` 30 s on `/api/voice-auth`). Owner step: set `CRON_SECRET` (1Password item `voice-token-cron-secret`, synced to `doddy-voice-token`); without it the daily retry does nothing and answers 503. App and server can ship in either order: only the new app calls `delete-conversations` and passes `userId`, and an old app just doesn't.
