# Studio: the job's dollar limit is enforced before each call
Studio's `STUDIO_JOB_LIMIT_USD` was checked only after a model call, so one call (up to 32k/64k output tokens) could cross it: with the fake provider and a $0.05 limit the job stopped only at ~$0.204 (reproduced first, test `studioBudget.test.ts`). Now each paid call gets a worst-case ceiling (prompt estimate, cache-write price, searches, `max_tokens` at the output price), `max_tokens` is clamped to the remaining budget (no call is sent if even a minimal reply doesn't fit: `cost_limit`), the ceiling is reserved and settled from reported usage, and an unknown-outcome call keeps 50% of its ceiling counted. Day/month reservations unchanged. Docs: `server/messaging/README.md` "Pre-call job budget".
Price table checked against platform.claude.com/docs/en/about-claude/pricing on 2026-11-09: Opus 5.5 $4/$20, Sonnet 5.5 $2/$10, Haiku 5.5 $0.10/$0.50 (>100K prompt $0.50/$2.50), Fable 5.1 $10/$50; cache write 1.25x, reads 0.05x (Fable 0.025x, Haiku 0.1x); web search $10 per 1,000, web fetch no extra charge, code execution free with web tools: all match `models.ts`, no change. Studio's models are unchanged.
