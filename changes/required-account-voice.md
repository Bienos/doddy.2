Voice token server, step 2 of decision `2026-11-08-required-account`: `/api/voice-token` also accepts a Doddy account's access token (a Supabase user: Apple, Google or a code by email) when `SUPABASE_URL` is set. The server checks it itself against the project's published keys, with the backend's rules (ES256/RS256, issuer, audience, role, not anonymous, not expired, Apple/Google/email, never a password). The token gets its own limit bucket, `account:<id>`. Unreadable keys answer 503, never 401. The server's own Apple sign-in, sign-out and delete are unchanged.
