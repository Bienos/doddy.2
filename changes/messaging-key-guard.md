Messaging server: refuse to start without the encryption key; key versions for rotation. A deployed server (`NODE_ENV=production`, `RENDER` set, or a public `PUBLIC_BASE_URL`) stops at start without `MEMORY_ENCRYPTION_KEY`; `MEMORY_ENCRYPTION_KEY_VERSION`, `_PREVIOUS` and `_PREVIOUS_VERSION` plus `scripts/reencrypt.mjs` rotate it (README, "Rotating MEMORY_ENCRYPTION_KEY"). No migration; stored rows stay version 1.
`render.yaml`: `NODE_ENV=production` and `npm ci --include=dev` on both messaging services. `secrets/manifest.json`: `MEMORY_ENCRYPTION_KEY_PREVIOUS` (record only) and the two version names.
Ran: `npm run build`, the whole messaging suite against Postgres 16, `node tools/secrets/sync.mjs check`, the secrets tool tests, `scripts/ci.sh --only checks`. Not run: a deploy, or a rotation on the live database.
Owner: before deploying, check `MEMORY_ENCRYPTION_KEY` is set on the live service (made by hand; Render sets `RENDER`, so it counts as deployed and won't start without the key; its earlier `calls: true` startup log implies the key, not re-checked); if `NODE_ENV=production` is added there by hand, change its build command to `npm ci --include=dev && npm run build` too.
