Voice token server: the server's half of "one token per server" (items 1 and 3 of `docs/decisions/2026-11-12-one-token-per-server.md`). A new action, `POST /api/voice-auth` `account-session`, takes a Doddy account's token once and answers with the voice server's own session for the account: the 10-minute access token and rotating 30-day refresh token it already makes for Apple voice accounts, bound to `account:<id>`. `/api/voice-token` takes those and, for this release, still takes the Supabase token, so installed apps change in no way: nothing in the app calls the new action yet (the app half is a separate pull request). Details, limits and rollback: `server/voice-token/README.md`, "One token per server".
- **Same account, same limits.** Both kinds of token come out as `account:<id>`, so the per-account hour and day, the new-account day and pool, the fair share and the daily ceiling count a person once; tests run both kinds in every order against an in-memory store and a real Redis. The `voice_token` log line now carries a fixed word, `auth` (`account_token`, `account_session`, `apple_session`), so the share still using the Supabase token can be read before it stops being accepted.
- **The new action** is limited per account and per caller address with the sign-ins' numbers and settings (no new setting), in buckets of its own, counted only after the account's token checks out; same body-size, method and error answers as its neighbours. `apple-link`, `apple-revoke` and `delete-conversations` still take the Supabase token only.
- **Ending a session** reuses what Apple voice accounts have: `sign-out`, refresh rotation with reuse detection, `delete-account`. New: `delete-conversations` (the first call when a Doddy account is deleted) also ends every voice session of the account. An ended session's access token is refused at once at this server, because every request looks its session up.
- **Fix found while reusing the machinery:** refreshing a session used to reset the sealed Apple token's life to 30 days, which would have cut a Doddy account's 400-day link short; a refresh now only lengthens it. Apple voice accounts are extended as before. `createSession` takes no Apple nonce for the new action.
Ran: `node --test test/*.test.js` in `server/voice-token` (222 pass, 0 skipped: the 175 earlier tests plus 47 new, including a real local redis-server; the tests were seen red before the code), `scripts/ci.sh --only checks`, `scripts/ci.sh --only node`. Not run: anything against Vercel or the live Upstash store; nothing deployed; the app is untouched and not compiled.
Merging ships it: Vercel builds `doddy-voice-token` from `main`. **No setting has to be set**, and nothing changes for installed apps. The later app pull request will touch `DoddyApp/Features/Voice/VoiceTokenClient.swift` and `DoddyApp/Features/Account/DoddyAccountApp.swift` (`voiceAccountToken`). Rollback: revert; `account-session` answers `400 unknown_action` again and the app falls back to the Supabase token it holds; sessions already made keep working under the earlier code (README).
