iPhone: the app now asks the voice server for a session of its own for the signed-in Doddy account (`POST /api/voice-auth` `account-session`, merged as #481) and sends that session's access token to `/api/voice-token`; the account's Supabase token is sent only when no session can be had, as before. The session (access and refresh token, and the account they belong to) is one Keychain item, renewed with the rotating refresh token (the new pair is kept every time, a spent token is never sent again, asks at once share one refresh). A 401 for the session forgets it and asks for a new one once, then falls back. An older server (`400 unknown_action`), a limit, a busy server or no connection means no session and the account's token, with nothing remembered; a rate limit at `/api/voice-token` is shown exactly as before. Signing out, deleting the account and another account taking the iPhone over forget the pair at once and keep the voice server's sign-out owed in a second Keychain item until the server answers (tried now, at each launch and at each sign-in); nothing is called ended unless the server said so (DOD-08, DOD-11). Both items are in `DeviceKeychain` and `docs/architecture/DEVICE_DATA_STORES.md`. Decision `2026-11-12-one-token-per-server` (voice server's part, app half).
