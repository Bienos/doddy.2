Item 5 (caching): only the assistant's instructions (about 950 tokens, same per locale) carry `cache_control`; notes, turns, photo/file and the question stay after it, unmarked. It only pays when a second question comes within five minutes (a write costs 1.25x input, a read 0.1x on Haiku 5.5), so the ledger's cache columns are how to measure it; whether the hit rate is real is not measured yet. Not applied: the backend's Ask/document paths (outside this task).

Item 7 (polling), measured on a fake clock: one idle hour is 1,801 passes at a fixed 2 s and 124 with the back-off (93% fewer) per queue loop (dispatch, errand, studio). Real-DB test: a message queued while the loop is in a 4 s wait is sent in about a second via NOTIFY. Real production savings depend on traffic and were not measured.
