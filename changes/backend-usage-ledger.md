Backend (not voice): Anthropic cost is now attributable per account, cheaper where it safely can be, and no longer paid twice for a retried Ask. Four items from `Doddy-optimization-research-2026-11-09`, one commit each.
1. Usage ledger: every call from Ask Doddy, chat, Ask Claude and documents writes a content-free `claude_usage` row (account, provider, model, feature, request id, call number, initial/continuation/retry, outcome, error code, stop reason, input/output/cache-write/cache-read tokens, cost in nano-USD from the price table in `usageLedger.ts`). Failures and timeouts are rows with usage "unknown" (null), never zero. No prompt, material or answer text. `Store.claudeUsageByAccount` is the per-account read; I did not add an owner route (it would touch `web/owner.ts`, routes and the generated owner fixtures). Erasing an account deletes its rows; rows are pruned at 400 days. Not voice metering.
2. Prompt caching: `cache_control` only on a fixed system prompt long enough for the model's minimum (512 tokens for Sonnet 5.5 and Haiku 5.5, from the docs; by a low 4-chars-per-token estimate), and on document continuation calls once the re-sent conversation reaches it. Today that marks the chat's system prompt (about 850 tokens) and long document continuations; Ask Doddy's (about 350 tokens) and Ask Claude's stay uncached. User material is never in the marked system part. A provider 400 on a marked request is retried once unmarked. Model unchanged.
3. Ask dedup (`docs/decisions/2026-11-09-ask-request-dedup.md`): same account and request id inside 10 minutes returns the first answer (or waits for the running one); other accounts, other questions and failures never share; answers live in process memory only and are dropped on account deletion. Existing tests that re-sent one fixed id now send fresh ids, as the app does.
4. Provider-file cleanup: a generated file's Anthropic id is written to `provider_file_deletions` before the first delete, confirmed only by a 404 read-back, retried hourly with 1 min to 6 h backoff, reported as stuck after 10 tries (counts only, no id in logs); a deletion failure never fails the document.
Sources checked 9 Nov 2026: platform.claude.com/docs/en/about-claude/pricing (Sonnet 5.5 $2/$10, cache write 1.25x, read 0.05x; Haiku 5.5 $0.10/$0.50, read $0.01, dearer above 100k prompt tokens; Haiku 4.5 $1/$5) and .../build-with-claude/prompt-caching (minimums, order, usage fields, automatic caching). Code-execution container time is billed separately and is not in the ledger's cost.
Ran: `cd backend && npm run build` and the whole backend suite with the dot reporter, 712 tests, 0 failures; new files `usage-ledger`, `prompt-cache`, `ask-dedup`, `provider-file-cleanup` tests. Not run: live Anthropic calls (so whether Anthropic accepts a top-level `cache_control` together with a skills `container`, and whether the JSON-schema `output_config` keeps a cache hit, is unverified; the ledger's cache counters will show it, and the unmarked retry covers a rejection), a multi-instance deployment, `scripts/ci.sh`.
Deploy: no env or config change. The new tables (`claude_usage`, `provider_file_deletions`) are `CREATE TABLE IF NOT EXISTS` in `SCHEMA_SQL`, so the first server start after a deploy creates them; nothing is applied from this branch.
