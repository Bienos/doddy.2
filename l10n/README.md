# Languages: how Doddy's screens are translated

Status 7 Nov 2026: the catalogs carry **English, Polish and eight machine-translated drafts**: Spanish, German, French, Simplified Chinese, Japanese, Brazilian Portuguese, Italian and Croatian. The drafts compile with the app in the hosted Mac CI, but none is recorded as seen on a device or read by a native speaker; `REVIEW_NOTES.md` lists what to check first and the decisions the owner has to make. This page says what exists, how a language gets added, and how a person switches. The translation prompt for the app is `TRANSLATION_PROMPT.md` next to this file; the one for the website is `WEBSITE_TRANSLATION_PROMPT.md`. The website is translated into the same nine languages from its own tables in `l10n/site/` (see `site/README.md`, "Languages").

## What exists

- **No library is needed.** The app uses Apple's String Catalogs (`Localizable.xcstrings`, one per target: app, widgets, share extension, Watch, Watch widgets, Mac, Mac widgets; the Watch and Mac apps are paused, ADR-572, but their catalogs are still written). SwiftUI looks up every `Text("…")`, `Button("…")`, `Label`, `Toggle`, `Section` and similar literal in the catalog at run time, so the whole design is covered without touching a screen (ADR-223). Adding a language is adding a column to the catalogs, not changing views.
- **The catalogs are generated, never edited by hand.** `tools/build_strings_catalog.py` reads every language table in this folder: `l10n/<code>.json` (English key → that language), `l10n/<code>_infoplist.json` (permission prompts) and `l10n/<code>_shortcuts.json` (Siri phrases), and writes all the catalogs with one column per language, plus the `CFBundleLocalizations` array in both Info.plists (ADR-458). `--check` runs in CI (`scripts/ci.sh --only checks`) and fails when a catalog or plist is stale, a placeholder differs, a prompt or phrase is missing, or a translated line's English has left the app.
- **Coverage on 9 Nov 2026** (`--check` prints it): Polish has 3,215 of 3,241 UI strings; each of the eight drafts has 1,246. Since 9 Nov the generator also finds both words of a condition that is a call's first argument, `Text(isOn ? "On" : "Off")`: SwiftUI looks them up like any literal (its `StringProtocol` initialisers are disfavoured overloads), but until then they never reached a catalog, so they showed in English in every language. Every language has all 14 permission prompts and 29 Siri phrases. A string with no translation shows in English. Strings built at run time (values inside the string, error messages) stay English in every language until they move to `String(localized:)` (`docs/implementation/POLISH_SCREENS_STATUS.md`). Text sent to the voice agent stays English on purpose.
- **Shipped languages** are the `CFBundleLocalizations` array in `Config/Doddy-Info.plist` and `Config/DoddyMac-Info.plist`, which the generator writes from the tables it finds.
- **A string with a value inside** (`Text("\(count) to go")`) has no key the generator can find, so it shows in English in every language. Write it as a format string: `Text(verbatim: String(format: NSLocalizedString("%@ · %lld to go", comment: ""), name, count))`, with `%lld` for an `Int` and `%@` for a `String` (make a `Substring` a `String` first). `Button`, `Label`, `Toggle`, `Stepper`, `DisclosureGroup`, `confirmationDialog`, `accessibilityLabel` and `accessibilityHint` take the `String` itself and show it as it is. A string that is only values (`"\(n) / \(max)"`) just needs `Text(verbatim:)`. A translation keeps the same placeholders in the same order (`--check` fails otherwise), so Polish puts the number after a label: "Pozycje: %lld" reads right for any number. English plurals get two keys ("1 cancelled event hidden." and "%lld cancelled events hidden."). On 8 Nov 2026 every such string was converted except the 40 in `DoddyApp/Features/Voice/VoiceView.swift`, which wait until no other pull request has that file open. Text sent to the voice agent stays English on purpose. What's left: `grep -rnE '(Text|Button|Label|Toggle|Section|navigationTitle|Picker|LabeledContent)\(\s*"[^"]*\\\(' DoddyApp Shared DoddyWidgets --include=*.swift | grep -v verbatim`.
- **The voice speaks any language already.** OpenAI Realtime is a voice choice (ElevenLabs is the default again since ADR-546; before that OpenAI was, ADR-442). The session the app sends (`OpenAIRealtimeWire.sessionUpdate`) names the language set in Settings › Voice and personality › Starts in (Automatic plus 25 European languages, `ConversationLanguage`). With nothing stored that is Polish (ADR-573), and Polish also gets a line telling the model to speak Polish. Only with Automatic (and a phone not set to Polish) does it name none; then the transcription model detects the language it hears, so Doddy answers in whatever language the person speaks, Chinese or Japanese included. The ElevenLabs switch is the exception: its agent is limited to the 37 languages it has presets for (`voice-agent/session.json`). The same setting goes to ElevenLabs.

## How a new language gets in

1. **Translate.** Run `TRANSLATION_PROMPT.md` for the language. It works through `tools/l10n_batch.py`: `show` prints the next strings by number with the English and the Polish, `merge` puts the answers under the right keys (refusing empty lines and placeholder mismatches), `status` says what is left. The translator never types a key. Result: `l10n/<code>.json`, `l10n/<code>_infoplist.json`, `l10n/<code>_shortcuts.json`.
2. **Build the catalogs:** `python3 -I tools/build_strings_catalog.py`, then `--check`. The code lands in every catalog that has one of its strings and in both `CFBundleLocalizations` arrays. Commit the tables, the regenerated `.xcstrings` and the plists together.
3. **See it on a device** (needs a Mac): build, run with `-AppleLanguages (<code>)` or set the language in iOS Settings, and check Home, capture, Settings and the voice screen at default and AX5 Dynamic Type, light and dark, for truncation. `DoddyUITests/PolishSmokeTests.swift` is the pattern for a smoke test per language.
4. **Native review before release.** ADR-234 applies to every language: machine translation is a draft; the privacy texts and the AI disclosure are reviewed first.

A table that has not been through steps 3 and 4 is a draft the app can show, not a language Doddy supports.

## How a person switches language

- **In Doddy:** Settings › App language (ADR-459). **Polish until the person picks another** (owner, 21 Oct 2026, ADR-573; English was the default from 13 Oct). The list shows each language by its own name, plus "Same as this iPhone". iOS reads the language when an app starts, so a change shows the next time Doddy is opened; the footer says to close it and open it again. The choice is written to the app's own `AppleLanguages` setting by `AppLanguageStore`; the rules (Polish default, keeping a language set in iOS Settings, "same as this iPhone") are `AppLanguage` in DoddyCore, tested on Linux.
- **In iOS Settings › Doddy › Language:** the same setting, and the only one that also moves widgets, Siri phrases and the system's permission prompts. A language picked there is kept if the person has made no choice in Doddy.
- **Any iPhone starts Doddy in Polish** until the person picks their language (ADR-573). Builds before ADR-573 wrote English on first launch; once (`polishDefaultApplied` false), with no choice made in Doddy, exactly that English is replaced by Polish. English picked in Doddy, or set again in iOS Settings › Doddy afterwards, stays. iOS has already chosen the language of the launch that writes the setting, so Polish shows from the next launch.
- **Voice:** Settings › Voice and personality › Starts in. Polish when nothing is stored (`ConversationLanguage.default`, ADR-573); a stored Automatic stays automatic and follows what the person speaks.

## Limits to keep in mind

- **Two wordings still assume Europe, or English and Polish.** Neither stops a conversation in another language: the opening line falls back to English for a language with no `first_message` in `voice-agent/session.json` (no Chinese, Japanese, Korean, Arabic or Hindi there); Doddy's greeting is English or Polish (`WakeGreeting`).
- **Arabic and Hebrew** run right to left. SwiftUI mirrors layouts, but the screens and the Doddy art need a design review before either ships.
- **Plurals.** The English source has no `.stringsdict` rules; counts are formatted in code. Languages with several plural forms (Polish already, then Czech, Russian, Arabic…) get the English rule's shape. Fix per string when a native reviewer flags it.
- **Length.** Translations run longer than English (German, Finnish and Polish especially). Screens must let text wrap; that is a design rule already (`BRAND_GUIDELINES.md` 3.8).
- **Don't claim** a language is supported until step 3 has been run on a device and step 4 is recorded.
