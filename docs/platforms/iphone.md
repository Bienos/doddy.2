# iPhone and iPad

**Build:**
- `make project`, scheme `Doddy`: the shipping build. The Apple Watch app is paused (ADR-572) and is not in it.
- `make project-iphone`, scheme `Doddy`: the same with no entitlements, so a free Apple team can sign it. The widgets and "Save to Doddy" are left out of the app, because they need the App Group (owner, 23 Oct). It has no Apple Health: the Health screen says this build can't use it (owner, 25 Oct; to try it, see `project-iphone.yml`).
- iPad is the same app target (`TARGETED_DEVICE_FAMILY 1,2`). The minimum is iOS 17.0 (`project.yml`).

**State:** this is what the owner builds and uses. The known-good branch and the unmerged changes are in `/STATUS.md`. iPad work (sidebar, fixes) is in `docs/implementation/IPAD_STATUS.md`; it compiles in the hosted Mac job (whose iPad sidebar UI test is skipped on the iPhone simulator) and hasn't been seen on an iPad. **The default branch compiled in the hosted Mac job** at `c82bd1bd` (run 42385757551, 7 Nov); since ADR-811 every push to `main` runs that job, so the newest run on `main` is the current answer. That is not a run on a device, and almost nothing merged since 20 Oct has a recorded device check.

## Voice: the core of the app
- Action Button: the island comes first (13 Nov 2026, decision `2026-11-13-island-first`). A press puts the island up as "Connecting…" as soon as the checks that need only the iPhone pass (terms, Face ID lock, Live Activities, microphone, account and voice-data gate), before it waits for the notes store, the profile, the conversation's set-up, the audio session, the token and the connect; the conversation then takes that island over. A press that is refused or cancelled after that ends the island at once (`TalkIslandFirst`, DoddyCore). The waves still come only with the provider's events. The big island opens only with "Expand when Doddy speaks" on (decision `2026-11-12-action-button-audio-and-island`). A four-second readiness timeout cancels the attempt and offers to open Doddy; the connect runs on after the intent returns. Not compiled here and not measured on a device: the log line `talk start timing: island shown …` gives the number.
- Home's character button starts connection setup in the tap's turn, alongside its hop; the former 0.35-second pre-start animation wait is removed. Its visual cleanup stays at 1.15 seconds. The persistent stage's direct tap was already immediate; this is not a claim that all prior taps paid the delay or all three seconds are eliminated.
- Provider network preparation (decision `2026-11-11-prepare-voice-network`): foreground voice readiness also requests LiveKit's `prepareConnection` at most once per two minutes, without a token or room join and independently of token preparation. The custom ElevenLabs host takes the SDK's HTTPS HEAD branch; the SDK's actual conversation uses a separate Room. Preparation never blocks Talk. No pre-tap microphone or personal context; no measured speedup yet. `voice transport timing` reports SDK room/microphone, agent-ready, init and total durations; unavailable metrics stay unavailable.
- Token preparation follows foreground sign-in/restore and consent changes, and runs again after the user ends a conversation. A Home tap joins a matching preparation already in flight (`VoiceTokenSupply`) instead of fetching a second token. Single use, account/server binding, the 4-minute expiry and unused-token cool-down still apply. This prepares only a credential, never a room or microphone. `voice first speaking event after start` times Home's tap through its access check to the first SDK speaking event (which may precede audible playback), with only seconds and the token source. No claim of instant audio: device tap-to-audible-speech timing still needs measurement.
- Startup uses a bounded SQLite snapshot (up to 24 eligible, non-private notes and 30 list names/counts), not the screens' full memory/correction/media reload. Overflow and unavailable storage are named; deeper notes/lists are read on demand. Learning/errands use completed cached context only, and translator startup skips the personal snapshot. `Voice startup context` is timed separately. Decision: `2026-11-09-bounded-voice-startup`; device latency has not been measured for this change.
- What the person asks for runs at once (decision `2026-11-11-asked-for-runs-at-once`): looks at their own things, account reads, `ask_claude`, `make_document`, `look_at_screen` while they share their screen, and Doddy's own stopwatch, focus, wind-down, list adds and ticks, follows and the training plan screen show no card and wait for nothing (`AskFirst.runsAtOnce` in DoddyCore; 51 tools run at once, 65 keep a card). A change, a send, a delete, a call or paid background work still needs a tap. Each Connections switch is still allowed once on its own sheet. DoddyCore tested on Linux; the app half not compiled here, not seen on a device; the live agent still speaks its question until it is synced (OWNER_QUEUE 37).
- Cards pop up (decision `2026-11-10-cards-pop-up-and-results-in-messages`). A card that waits for a tap, or a file, contact, parking spot, presentation, photos, lost-wallet steps, BLIK details or list items to choose from Doddy just showed, opens the conversation's sheet half height as a card (`VoiceView(asCard:)`, `HomeConversation.resultsToShow`, `RootView.presentCard`). "Show the conversation" opens the transcript. A new ask replaces a card still waiting, and nothing on the replaced card runs (`VoiceToolReply.replacedByNewerAsk`). `open_map` with `from`/`mode` opens directions (`MapTrip` in DoddyCore). The transcript footnote is a one-time notice. Since 13 Nov 2026 a new line scrolls the transcript to the end of lines and cards, so a card isn't pushed off screen, and a file made by voice shows what was asked for on its card and in its Messages bubble (`ThreadDelivery.madeFileBrief`; decision `2026-11-13-voice-screen-capsule-and-cards`). Not compiled here; not seen on a device.
- A file still being made doesn't pop up the card (decision `2026-11-13-file-being-made-island-note`). Only a ready file does (`MadeFileStart.popsUpCard` in DoddyCore). Instead a small black note drops out of the island at the top of Home for 6 seconds: what Doddy is making, its name, and "It lands in Messages in a minute or two" (`MadeFileIslandNote.swift`, `VoiceSessionController.madeFileNote`). It has no buttons, and a tap puts it away sooner. The transcript shows a quiet row with nothing to tap. In a private conversation the file never reaches Messages, so the row keeps Open and the note says to open it from the transcript. The agent hears the phone's own words, not the server's line, which said a card was on the screen: no card, no tap, Messages or the transcript (`MadeFileStart.voiceReply`). The real island's subtitle is "Takes a minute or two" (was "Its button is in Doddy"). Not compiled here; not seen on a device.
- **Code:** `DoddyApp/Features/Voice/` (27 files). Session: `VoiceSessionController.swift`. Screen: `VoiceView.swift`; on Home, `HomeConversation.swift`. Provider config: `VoiceConfig.swift`. The island's activity: `VoiceLiveActivity.swift`; the loudness of Doddy's voice: `AgentVoiceMeter.swift`. The wake word (`WakeWordListener.swift`) was removed with Hey Doddy (ADR-549).
- **Agent:**
  - ElevenLabs `agent_0501m4et27vyeawrwqfdxxfszfa6`. The prompt and tools are in `voice-agent/` (`instructions.md`, `tools.json`, `session.json`). `python3 -I scripts/voice_agent_spec.py check` validates them.
  - The live agent is changed by the owner, never from the app.
  - The app sends 13 dynamic variables at start: the 12 `voice-agent/session.json` lists plus `opening_line` (notes, lists, profile, `learned_context`, errands, recent conversations, personality, the opening line and others; `VoiceSessionController.swift`). A variable the live prompt requires but the app doesn't send stops the call before it starts.
- **Provider:** ElevenLabs only. OpenAI Realtime, the voice picker and the call rehearsal were removed on 9 Nov 2026 (decision `2026-11-09-elevenlabs-only-voice`), and the choice of Doddy's voice with its samples on 12 Nov 2026: Doddy speaks only in the agent's own voice; Speed, Expressiveness and "Starts in" stay (decision `2026-11-12-one-voice`); `docs/implementation/VOICE_PROVIDER_TEST_STATUS.md` is history. A Debug build's developer connection reaches the ElevenLabs agent directly (ADR-551, ADR-633), and only while the agent's authentication is off. It is on since 8 Nov 2026: when ElevenLabs refuses the connection, the app turns the Debug switch off and carries on through the token server if the iPhone has a voice session, or asks to sign in (`DeveloperVoiceConnection` in DoddyCore).
- **Audio session:** one owner, `AudioSessionOwner.swift` (ADR-695; the rule is `AudioSessionPolicy` in DoddyCore). Anything new that records or plays sound registers there, asks `claim` before setting the session up and calls `release` when done; it never switches the session off itself. A phone call during a conversation follows `VoiceInterruptionPolicy` (ADR-696).
- **Status docs:** `V1_VOICE_STATUS`, `V3_ISLAND_STATUS` (Dynamic Island), `HEY_DODDY_STATUS` (history: removed, ADR-549), `OPENING_SCENE_STATUS` (listen-on-open; the basketball intro is history, removed 9 Nov 2026).
- **To debug a voice problem,** look at the ElevenLabs conversation log for the agent first:
  - no conversation at all means the app failed before connecting;
  - a conversation with no messages means the session started without its start data.

## Doddy account (decision `2026-11-08-required-account`, in progress)
Every user signs in with a Doddy account, using Apple, Google or a code sent by email, and the app goes no further without one. **Off until the owner fills in `DoddyAccountsURL` and `DoddyAccountsPublishableKey` in `Config/Doddy-Info.plist`** (both public; empty today). While they are empty, and in every UI-test launch (`-inMemoryStore`), the app behaves exactly as before.
- **Rules (DoddyCore, tested on Linux):**
  - `Account/DoddyAccount.swift`: the Supabase Auth requests (an email code, Apple's identity token, Google through the browser with PKCE, refresh, sign-out), the rules for addresses, codes and sessions, and the calls that bring an iPhone's earlier data into the account (the backend's two-step `link-device`: the device session asks for a one-time code, then the account links with it; `undoBackendLink`, which no screen offers yet; its `probeBackend` check; the messaging server's `accounts/sign-in`). `DoddyAccountTests`, 19 tests.
  - `Account/DoddyAccountModel.swift`: the signed-in state the screens show. A sign-in counts only once the Keychain kept it, and each kept sign-in adds one to `signInCount` (a refresh doesn't); one refresh at a time; a refused refresh signs out. `DoddyAccountModelTests`, 12 tests.
  - `DoddyServerClient(accountSignIn:)`: with no messaging token it signs in with the account, and makes an anonymous account only while the server isn't set up for accounts. `ServerAccountSignInTests`, 4 tests.
- **The app (`Features/Account/`, `Features/Welcome/`; not compiled, no Xcode on the Linux machine that wrote it):**
  - The welcome's sign-in sheet shows Apple and Google. Email is off for now (`SignInSheet.offersEmail`, decision `2026-11-09-email-sign-in-off-for-now`); `EmailCodeForm` stays for when it returns. There is no "without an account" button, and the welcome stays until the person is signed in, including after a sign-out (`RootView.accountRequired`). Every kept sign-in closes the welcome (`signInCount`); someone already signed in when it shows (Settings › "Show the welcome again", or a reinstall, which keeps the Keychain) sees which account and "Continue". Before this, a sign-in made while already signed in left the welcome up with nothing happening (TestFlight build 20, 9 Nov).
  - Settings › About › Your Doddy account (one page down since 11 Nov 2026): who is signed in, Sign out, and Delete my Doddy account (messaging data first, then the backend, which also removes the sign-in at Supabase, then an old voice account; each step only after the one before was confirmed). Since decision `2026-11-12-account-deletion-truth` (rules `Account/AccountErasurePlan.swift` in DoddyCore, `AccountErasurePlanTests`; app side not compiled here): with no messaging token on the iPhone, or a refused one, the app mints the account's own token (`accounts/sign-in`) and deletes once more, and only a 204 (or a server that takes no Doddy accounts) counts; the backend erase makes or renews its session first, and a device ID without a session is a failure, never "nothing there", so "Delete voice account" keeps the voice account until the backend confirmed.
  - Sign in with Apple and deleting the account (decision `2026-11-09-apple-revoke-for-doddy-accounts`): right after an Apple sign-in the app sends Apple's one-time code to the voice token server (`DoddyAccountServers.linkAppleRevocation`, action `apple-link`); deleting the account first asks the server to revoke it at Apple (`revokeApple`, action `apple-revoke`). Apple failing doesn't stop the deletion; the result says how to remove Doddy in the Apple ID settings. **Does nothing until the voice server has the Apple key (OWNER_QUEUE 24); not compiled or run on a device.**
  - The session is kept in the Keychain (`DoddyAccountKeychain`, this device only).
  - Deleting the account also deletes its voice conversations (decision `2026-11-12-voice-conversations-per-account`): after Apple's revoke and before the backend, `DoddyAccountServers.deleteVoiceConversations` asks the voice server (`VoiceAuthAPI.deleteConversations`, action `delete-conversations`, the account's token and this iPhone's old per-install id `PreferenceKey.voiceUserID`). What counts as confirmed is `VoiceConversationErasure` in DoddyCore: nothing pending is "deleted"; some pending goes on and the end says they are still being deleted (the server retries every day); no answer stops there and the person stays signed in, like the messaging step; an old server without the action claims nothing. `VoiceTokenClient` reads the `userId` the token answer now carries into `VoiceTokenUserIDs`, and `VoiceUserIDPolicy` chooses it over the install id. **Not wired yet:** `VoiceSessionController` still starts every conversation with the install id (it is a file other pull requests change); the wiring is in `changes/voice-conversations-app.md`. The first-conversation agreement has its state and an off switch (`VoiceConsent.requiredVersion` is nil) and no screen: the words wait for the owner and a lawyer. **Not compiled:** the app files (no Xcode here); DoddyCore's tests ran on Linux.
  - Each server switches separately (`DoddyAccountServers`). The backend gets the account's token once it has linked or accepted the account; the messaging server gets a device token for the account once it signed this iPhone in. Until a server says yes, the iPhone keeps its device session or anonymous account there. The voice token server gets the account's token unless this iPhone still has its own voice session. Voice may start with the account (`VoiceAuthSession.hasVoiceAccess`).
  - Account error messages have Polish lines (`DoddyAccountWords`).
  - **Local data belongs to the account that made it** (decision `2026-11-12-local-data-owner`; rules `Account/LocalDataOwner.swift` in DoddyCore, `LocalDataOwnerTests`; app side `Features/Account/LocalDataOwnership.swift`, not compiled here). The iPhone records which account its notes, lists and Messages thread belong to: the first account signed in, or another one only when those are empty (checked after each sign-in and at launch). The Messages copy for Doddy Web, Memory on calls, notes and conversations kept on Doddy's server, and Logbook each ask `LocalDataOwner.upload(for:)` first and send nothing to another account or while nobody is signed in; the web switches and Logbook then say "This iPhone holds Doddy data from another account, so nothing from it is sent to yours." A sign-out turns Memory on calls and both "Keep on Doddy's server" switches off, forgets Logbook's counts for that account (its switch stays as set), and ends the older voice session from Sign in with Apple. The voice token client and the voice sign-in requests refuse redirects and read answers only from the address asked (`BearerHost`).
- **Known gaps:**
  - Notes stay on the iPhone after a sign-out, so whoever signs in next on the same iPhone sees them. The sign-out dialog says so; whether to clear them is an owner decision. Since decision `2026-11-12-local-data-owner` nothing of them is sent to the next account; an "Erase Doddy's data on this iPhone" button where that is found is still to come (TODO in `LocalDataOwnership.swift`).
  - Bringing an iPhone's earlier device data into an account at sign-in (`bringEarlierData`) doesn't ask the local-data owner yet.
  - The new layout has no UI test yet (UI-test launches have no accounts).
  - Google sign-in fails at Google with `redirect_uri_mismatch` until the Supabase callback is registered on the Google OAuth client (OWNER_QUEUE 25, read 9 Nov).
  - Retiring the old ways in (guests, device sessions, anonymous accounts, the Apple-only voice sign-in) is step 5.

## Logbook: usage counts (ADR-602; on by default, decision `2026-11-09-usage-counts-on-by-default`)
- **What it sends:** one summary a day to Doddy's backend, counts only: conversations (times, length, how they ended, language), what Doddy did by tool and result, notes and list items saved, tasks handed over. No words, note text, names or audio. Private notes and private conversations are not counted. Ways in and the translator are zeros until the app records them.
- **Rules (DoddyCore, tested on Linux):** `Logbook/LogbookDay.swift` (the shape and the server's checks), `LogbookBuilder.swift` (a day from the app's records), `LogbookSync.swift` (which days to send, the client, the upload), `LogbookModel.swift` (on by default, the switch, deletion confirmed by the server). `LogbookTests` 10, `LogbookModelTests` 7.
- **The app:**
  - `Features/Web/Logbook.swift` reads What Doddy did, the notes, lists and errands;
  - `VoiceSessionController.keepLog` counts each finished conversation;
  - `RootView` sends at launch, when Doddy comes to the front and when it goes to the back;
  - Settings › Doddy on the web › Logbook is the switch (`LogbookSection`).
- **Where it shows:** Logbook in Doddy Web for the person; the owner panel for the owner (next pull request).
- **Not run on a device.** Compiled by CI only.

## The hosted build on a pull request (ADR-680)
A `changes` job first works out which jobs the change can reach (`scripts/ci_needs_mac.sh`, `scripts/ci_groups.sh`). Then, side by side: the Linux groups `checks`, `swift`, `backend`, `node` and `messaging`, each `scripts/ci.sh --only <group>`, gathered into one `core` result (ADR-684); and `ios-build` (named `ci` until ADR-811) on a Mac (`scripts/ci.sh --app-only`: DoddyCore on Apple's Foundation, the app build, the unit tests and the UI tests, on one simulator; the native island test runs last and alone, under a watchdog, because the hosted simulator's drawing sometimes freezes during it, ADR-764). `core` and `ios-build` must both be green; a job the change can't reach is skipped and counts as passed. On a pull request the UI tests are the smoke classes only (`DODDY_UI_TESTS=smoke`) and the native island test is skipped, unless the pull request has the `full-ui-tests` label. Every push to `main` runs every job, the whole UI suite and a Release compile for devices (ADR-811). The Mac skips only what the Linux groups run and lists it as SKIPPED. Locally, `scripts/ci.sh` with no flag still runs everything; `DODDY_UI_TEST_WORKERS=2` runs the UI tests on two simulator clones, which a Mac with more cores than the hosted one may manage. For a design change to the Dynamic Island, the quick island-only run (ADR-618, Actions › iOS build and tests › Run workflow, `only: island`) gives pictures in 15 to 20 minutes.

**Pictures of every screen (ADR-820):** Actions › iOS build and tests › Run workflow, `only: screens`, runs `scripts/ci_screens.sh`: one build, then `DoddyUITests/ScreenAtlasTests`, which walks to about 90 screens and keeps a picture of each in the `screen-atlas` artifact (with `index.tsv`: reached or missed). Pictures only, offline (no voice agent, no server); not a substitute for the full run. In every other run those tests skip. Sample states for what the simulator can't reach by itself (conversation cards, a leaflet answer, a finished shopping task, the report) are `-screenFixture` launches in Debug builds (ADR-821). What each screen is and where it lives: `docs/implementation/SCREEN_ATLAS.md`.

### Messages local actions (9 Nov 2026)

With the updated messaging server, Messages offers eight local actions: save/search notes, create/read/add/check/remove list items, and create reminders. Each immutable payload needs a tap; the same local repositories and ReminderAction as voice verify the result. Private notes/lists stay out.
