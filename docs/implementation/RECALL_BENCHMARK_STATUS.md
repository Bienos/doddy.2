# Recall benchmark: status (ADR-211)
Date: 2026-10-10. Owner instruction: "start with #1", the first item picked from the DODDY AI agent research backlog: OP-016 (search quality benchmark harness) together with the measurement part of OP-008 (Polish search evaluation).

## What this adds
- **Test set:** `docs/quality/evals/recall_golden_v1.json`.
  - 40 invented everyday notes: 20 in English, 20 in Polish (keys, codes, appointments, sizes, recommendations, bills).
  - 76 questions: 40 in English, 36 in Polish. 66 have an answer and 10 should get "no match".
  - Each question lists the notes that answer it and is tagged with the kind of difficulty: `exact`, `no_diacritics`, `word_ending`, `cross_language`, `typo`, `spoken_number`, `paraphrase`, `possessive`, `should_miss`.
  - No real user data.
- **Runner and gate:** `Packages/DoddyCore/Tests/DoddyPersistenceTests/RecallBenchmarkTests.swift`.
  - It uses the real SQLite store, the FTS5 index, `RecallMatching` and `RepositoryRecallService`, with the app's limit of 20. Nothing is mocked.
  - The test fails if a question that passed, or put a right note first, in `docs/quality/evals/recall_baseline_v1.json` no longer does.
  - A separate test checks the scoring on hand-written answers, and another checks that the test set is well formed.
- **Report:** `docs/quality/RECALL_BENCHMARK.md`, generated by `scripts/recall_benchmark.sh`. It has a summary, a breakdown by language and by kind of question, every failure, and every question that was found but not first.
- Search itself is unchanged.

## First result (Linux, Swift 6.1.2)
| | Found | Right note first | Honest "no match" |
|---|---|---|---|
| All | 65/66 | 61/66 | 3/10 |
| English | 33/34 | 31/34 | 1/6 |
| Polish | 32/32 | 30/32 | 2/4 |

Word endings, typos, missing diacritics and spoken numbers all pass. Weak points found:
1. **The English "'s".** "What's", "Jake's" and "mum's" leave a one-letter word "s", which prefix-matches almost every note. "What's my blood type?" returns 18 notes instead of "no match". Questions with an "'s" show 17 wrong notes on average. The same happens with any single letter that is not a stopword: "ile witaminy D brać" shows 16 notes, because "d" matches every word starting with d.
2. **Short prefixes and typo matching between real words.** "car" finds "card", and "password" counts as a typo of "passport". So "netflix password" shows both wifi passwords and the passport note.
3. **No answer means no match only when no word matches at all.** One shared word ("number", "password", "car") is enough to show notes. That is honest (they are real notes), but the screen never says "nothing saved answers this".
4. **Different words for the same thing** ("heating check" for the boiler service) are not found. That is expected for word rules.

## Not done / limits
- **Labels are not human-reviewed.** Claude wrote the notes, questions and labels. The research asks for human-labelled accuracy, so a native Polish speaker should review `recall_golden_v1.json`.
- The questions were written after reading the matching rules, so they favour what the rules handle. The 98% "found" figure is an upper bound, not user accuracy. Real wording from a pilot or interviews is the next input.
- No semantic or on-device model comparison: OP-027 is not built, so there is nothing to compare against yet.
- No device run is needed: no app code changed.
