# Translating talks to its own agent, which has no tools at all

- **Date:** 2026-11-12
- **Decided by:** owner ("no nie powinien włączać agent funkcji podczas tłumaczenia żadnych", 12 Nov 2026, after being offered "a separate translator agent with only stop_translator" as one of three options)
- **Status:** the live agent exists since 12 Nov 2026 (`agent_8901m787fgppedy9kkvg7memny34`, "Doddy 6 · Tłumacz (bez żadnych funkcji)"); the app, token server and spec are in the pull request that carries this file
- **Replaces:** the translator rules inside the main agent's prompt, for a conversation that has the app's new build. They stay in the main prompt as the fallback (an older app build, or a token server that predates this).

## Why
In translator mode the app already refused every tool, but the main agent (118 tools, a prompt that says "do every look-up at once") still tried them: asked "where is the nearest pharmacy?" or "how much does this cost?" it sometimes called `find_places` or `look_at_screen`, said "Sprawdzam…" or answered, instead of translating. In ten conversations on each of two live versions of the main agent, with and without a prompt line that put translator mode first, the same mistakes appeared about 3 times in 10 (decision `2026-11-12-translator-more-languages`, owner queue item 50). A prompt can't remove a tool. The tool list is on the agent, and the app can't override it per conversation: the ElevenLabs Swift SDK's overrides stop at voice, language, first message and prompt, and the agent's own override for `tool_ids` is off (and should stay off, so a client can't hand itself tools).

## Decision
- **A separate ElevenLabs agent for translating**, made by duplicating the main agent (same voice, TTS model, authentication, language presets and overrides), then: a translator-only prompt (`voice-agent/translator/instructions.md`, 3,093 characters); `tool_ids` empty (the 115 client tools detached); the built-in `end_call` and `skip_turn` off, `language_detection` kept (it only switches the listening and speaking language, which the other person's language needs); soft-timeout filler off (it spoke "No…" before translations); no second voice and no audio tags (the model wrapped lines in `<Patryk>…</Patryk>` and added `[slow]`); ElevenLabs' default personality off; temperature 0.2; reasoning effort low; only the variables `translator_start` and `opening_line`.
- **The app asks for it.** A translator start (Home › Translate, or "Doddy, tłumacz mi rozmowę z …" in a normal conversation, which already starts a new conversation with no notes, profile or lists) fetches its token with the body `{"agent":"translator"}` (`VoiceAgentKind` in DoddyCore). It never takes the token held ahead for the main agent (`VoiceTokenWarmer.translatorToken`, with the same Pause all, voice data notice and same-account checks). Every other conversation sends no body, as before.
- **The token server picks the agent** (`server/voice-token`): `agent: "translator"` uses `ELEVENLABS_TRANSLATOR_AGENT_ID`, or, when that isn't set, the agent id in the code (public, like the main one's, so nothing has to be set on Vercel); any other agent name is a 400 before anything is counted. The same Doddy account session, rate limits and ElevenLabs key apply. The log says `agent: "translator"` or `"main"`, never an id or a token.
- **No tool means no `stop_translator`.** "Stop translating" is translated like any line; the user ends translating with End on the screen. The app still refuses every tool while translating (`TranslatorPolicy`), as a second wall.
- **One id, three places, one check.** `scripts/voice_agent_spec.py check --agent translator` (in `scripts/ci.sh --only checks`) fails if the spec's agent id differs from the token server's or the app's Debug connection, if the agent gets a tool or any system tool but `language_detection`, or if its languages differ from the app agent's.
- **Old and new meet safely.** An older app sends no body: the main agent, as before. A new app with a token server that predates this sends the body, which the old server ignores: the main agent's token, which still translates (and the app still refuses its tools).

## Consequences
- In translator mode no tool exists for the model to call: a look-up, a screen look, a call or a note can't happen, and a question can't be answered with one. In 34 typed conversation turns on the final agent (26 across 16 language pairs, then 8 Hindi) and 46 on it before reasoning low was set: no tool call and no "Sprawdzam"; the 20 turns before the second voice and the audio tags were removed had four `<Patryk>…</Patryk>` wrappers and one `[slow]`, and none after.
- Hindi with low reasoning: 8 of 8 right; with none: 4 of 8 (Polish or Arabic instead). First audio about 1.3 s either way (median), a few turns at 3–4 s.
- One more live agent to keep in step with `voice-agent/translator/` (the spec check covers the repo side; the live agent is read, not compared, by `voice_agent_spec.py`).
- The translator prompt rules now live in two places: `voice-agent/translator/instructions.md` (the translator agent) and the main prompt's section (the fallback). The text the app sends (`TranslatorPrompt.render`) is the same for both.
- Privacy is unchanged and says the same: both voices go to ElevenLabs, which keeps its own recording; the translator agent copies the main agent's recording setting (`record_voice` on, no retention limit). Turning recording off for this agent alone is now possible and is the owner's call (owner queue item 50).
- Voice "stop translating" no longer ends the mode; End on the screen does.
- Cost: no change in kind. Reasoning low adds a little LLM cost per turn; the prompt is 3,093 characters instead of 26,368, so each turn sends far fewer input tokens.

## Evidence
Live, typed conversations over the agent's WebSocket, started the way Home › Translate starts one, with the exact `{{translator_start}}` text the app builds (`TranslatorPrompt.render`): 80 turns on the translator agent across its settings, 0 tool calls; the same questions on the main agent (last two versions) were answered or looked up about 3 in 10. `make test-core`, `node --test` in `server/voice-token` (71 tests), `scripts/ci.sh --only checks` (results in the pull request). Not run: the app build (the hosted Mac job), a phone, speech (the checks typed, so recognition of the other person's language through `language_detection` and the new agent is untried), a native speaker's listen.
