# The Mac CI leaves the package tests to Linux on pull requests, builds Release in a job of its own, skips the Mac for pushes that can't reach the app, and waits in UI tests without XCTest's first second

- **Date:** 2026-11-15
- **Decided by:** owner ("jak można ogólnie te buildy przyspieszyć, ten iOS za długo trwa", then "okej to dawaj zaaktualizuj to żeby to było szybciej"; then, asked which bigger change to make, chose "Docs na main bez Maca")
- **Status:** accepted
- **Replaces:** nothing; narrows ADR-680 (DoddyCore on Apple's Foundation now runs on pushes to `main` and runs by hand, not on pull requests), moves ADR-811's Release compile into its own job, and narrows ADR-811's "every push to `main` runs every job" to every Linux group plus the Mac jobs when the push can reach the app

## Why
Measured from the job logs of 15 Nov 2026:

- Pull request, run 43716467848 (`ios-build`, 28.7 minutes of `scripts/ci.sh --app-only`, after 9.5 minutes waiting for a Mac): Swift package tests 3 min, build for testing 5 min, unit tests 5 min (30 s of tests), UI smoke tests 14.5 min.
- Push to `main`, run 43715540139 (70.5 minutes): package tests 2.6 min, build 5.5 min, unit tests 5 min (1 min of tests), UI tests 35 min, island test 2.4 min, Release build for a device **18.5 min**.
- In the unit-test step, 3.5 minutes pass between xcodebuild picking the simulator and the first test: the simulator's first boot on the hosted Mac. The restart before the UI tests (a warm boot) takes 30 s.
- The Linux `swift` job already runs the same DoddyCore tests in parallel with the Mac.

## Decision
1. ~~Boot the simulator in the background during the build.~~ Tried on 15 Nov 2026 and taken out the same day: while the simulator booted, `xcodebuild` stalled for about 2.5 minutes (package resolution took 2:46 instead of 12 s in run 43726575876 and 2:09 before it printed anything in run 43726567582) and build-for-testing took 8.3 minutes instead of 5 in the second, more than the 3.5 minutes the boot saved. The simulator boots as before, in the unit-test step.
2. `DODDY_SKIP_PACKAGE_TESTS=1` with `--app-only` leaves out the Swift package tests and lists them as SKIPPED. `ios-build` sets it on pull requests only; pushes to `main` and runs by hand still run them on Apple's Foundation.
3. `DODDY_RELEASE_BUILD=only` builds only Release for a generic iOS device, unsigned, with no simulator and no tests. The new job `ios-release` (pushes to `main` and full runs by hand, same image and Xcode, restores the package cache but never saves it) runs it beside `ios-build`; `ios-build` no longer builds Release (`DODDY_RELEASE_BUILD=0`). `ios-release` is not a required check; pull requests never run it, as before.
4. `ios-build` no longer installs PyYAML (about 15 s): its one reader, `scripts/check_platform_specs.py`, is in the `checks` group, which `--app-only` skips.
5. A push to `main` runs the Mac jobs (`ios-build`, `ios-release`) only when it changed a file that can reach the app, judged by `scripts/ci_needs_mac.sh`, the list pull requests already use (documents, change notes, `server/`, `backend/`, `site/` and the rest of its list take no Mac). `scripts/ci_push_changed_files.sh` lists the push's files from `github.event.before` to the pushed commit; when it can't (a new branch, a commit it can't fetch, a failed diff) the list is empty and the Mac runs. Every Linux group still runs on every push. On 15 Nov a docs-only merge (#520, run 43715540139) took a Mac for 75 minutes while pull requests waited for one.
6. The UI tests wait with `appears(timeout:)` and `pollUntil` (`DoddyUITests/UITestLaunch.swift`), which look about every 0.1 s, instead of XCTest's `waitForExistence(timeout:)` and `XCTNSPredicateExpectation`, which look the first time only about a second after they start, even when the element is already there. In the 15 Nov logs the full suite's 484 waits took 581 of its 1,995 seconds and 467 of them ended within 1.5 s; the pull-request smoke run's 145 waits took 177 of 687. All 177 call sites, the two label/gone waits in `MemoryBaselineTests` and `tapAndType`'s focus wait changed; the answers are the same, and "must not appear" checks still wait their whole timeout. `scripts/check_ui_test_waits.sh` (in `checks`) fails when a UI test uses XCTest's wait again.

## Consequences
- Expected: about 3 minutes less on pull requests from the package tests, and a `main` run that ends about 18 minutes sooner. These are estimates from the logs above; this pull request's own run is the first measurement of 1 and 2, and the first push to `main` after it measures 3.
- A difference that only Apple's Foundation shows in DoddyCore is found one merge later, on `main`, the same trade ADR-811 made for the full UI suite.
- A push to `main` now takes two Macs at once for about 20 minutes instead of one Mac for 18 more minutes, so the Mac minutes are about the same; while several merges land together, a pull request can wait a little longer for a free Mac.
- Item 6 removes up to a second after each wait, a second some test may have relied on without saying so (a sheet still sliding in when the next tap lands). The full UI suite runs by hand on this branch before the merge (Actions › iOS build and tests › Run workflow, `all`); a test that turns flaky gets an explicit wait for the state it needs, never the old second back everywhere.
- Item 1 was measured and undone (above): an early boot on the hosted Mac costs more than it saves.
- A skipped `ios-build` on `main` means the push couldn't reach the app, never that the app passed: the app's state at that commit is the last `main` run whose `ios-build` ran. Since 7 Nov each push to `main` has its own run that nothing cancels, so that run is always there to read (the gap ADR-811 closed came from a cancelled run).
- Not done: splitting the full UI suite across two Macs and caching compiled build products (the owner didn't choose them; the packages are about 2 of the build's 5.5 minutes, so a cache would save at most that). The UI tests also spend time scrolling (`XCUIApplication.reveal`: 79 of the smoke run's 687 seconds, 274 of the full suite's 1,995); opening the page under test directly needs launch arguments in `RootView.swift` and `SettingsView.swift` (one agent at a time), left for its own pull request.

Not run here: the hosted Mac jobs (no Xcode in this session), so the UI test change is not compiled here.
