# Pull requests wait on one shared hosted Mac: look at the capacity first, then narrow what needs it

- **Date:** 2026-11-12
- **Decided by:** proposal, owner approval pending. Written at the owner's request ("You do it", answering whether to write the CI queue up as a decision for the owner queue).
- **Status:** proposed. Nothing in `.github/` or `scripts/` is changed by this file.
- **Replaces:** nothing. Builds on ADR-497, ADR-680, ADR-684 and ADR-811.

## Why
Read on 12 Nov 2026 from the Actions API and the workflow files. Nothing was cancelled or re-run.

- **A pull request that is green on Linux still waits on the Mac.** #354's Linux groups finished by 01:29 UTC. Its `ios-build` job was queued at 01:22:35 and still queued at 02:07, 45 minutes later. `ios-build` is a required check, so the pull request can't merge until it runs.
- **Many runs share the Mac.** At 02:06 there were eight queued iOS runs (#346, #347, #349, #354, #356, #357, #358, #359) and runs in progress for #351, #352, #355 and two pushes to `main` (#345 and #348).
- **It isn't first in, first out.** #352's `ios-build`, queued at 02:00, started at 02:03, while #354's from 01:22 was still waiting.
- **A job takes a long time.** #353's `ios-build` ran from 01:30:00 to 01:57:32, 27.5 minutes. The comment in `scripts/ci_needs_mac.sh` gives about 52 minutes for a full run.
- **Why #354 needed the Mac at all.** It changes only server code, the voice-agent spec files and docs, plus two files under `scripts/` (`scripts/ci.sh` and `scripts/voice_agent_spec.py`). `scripts/ci_needs_mac.sh` run on #354's 33 changed files prints `mac=true` and names `scripts/ci.sh` first. Any path under `scripts/` falls through to "needs the Mac" (`*/*) return 1`), and the Mac job itself runs `scripts/ci.sh --app-only`, so a change to that file can change what the Mac runs. The filter's own header says it is deliberately conservative: a mistake in its list can only cost money, never skip a needed build.
- **Pushes to `main` run everything** on the Mac, all UI tests included (ADR-811), so each merge adds a full run to the same queue.

Not measured, because it isn't readable from here: whether GitHub caps how many macOS jobs run at once on this account's plan, and what the Mac minutes cost.

## Decision (proposed, in this order)
1. **The owner looks at the capacity first** (Settings › Actions, and the plan's usage page): is macOS concurrency capped, and by how much? If volume is the whole story, 2 and 3 help. If it is a plan cap, 4 is the real fix.
2. **Narrow `scripts/ci_needs_mac.sh` for helper scripts the Mac job never runs.** List them by name (for example `scripts/voice_agent_spec.py`), only after confirming that `scripts/ci.sh --app-only` doesn't call them. This would not have saved #354, which also changed `scripts/ci.sh`, but it saves pull requests that touch only such a script.
3. **Keep Linux-only steps out of `scripts/ci.sh`.** Move them into a file the Mac job doesn't run, so adding a check no longer counts as a change to the Mac path. This is the change that would have saved #354. It is a refactor of the CI entry script and needs its own pull request and a run on `main` to prove nothing was skipped.
4. **Add capacity** if 1 shows a cap: a larger or additional macOS runner. It costs money (the filter's header prices a run at about $3.20), so it is the owner's call.

## Consequences
- A narrower filter can skip a Mac build that was needed. `main` runs everything on every push (ADR-811), so the miss would show there after the merge, not before. That is the trade the owner accepts with 2 and 3.
- Nothing changes until the owner decides. Until then every pull request that touches `scripts/`, the app, the string catalogs or `voice-agent/instructions.md`, `tools.json` or `session.json` waits on the Mac.
