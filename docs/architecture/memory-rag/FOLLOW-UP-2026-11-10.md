## Remaining work, and why it cannot be called complete

1. **Account isolation:** `AppEnvironment.shared` opens one installation-wide database before account gating; notes, profile, learning, recordings, Messages, media and other stores share it. Siri/list intents, widgets/Spotlight, notification/background paths and synchronization run outside the login screen. A safe implementation must partition or fence all of these together, rebuild on identity transitions and cancel or reject stale async work. The old store has no trustworthy owner identifier. Preserve it as unclaimed; never infer ownership from the next sign-in. Existing UI-test account bypasses do not establish isolation.
2. **Linked deletion:** voice recaps are saved as ordinary notes without a stable conversation-ID-to-memory-ID relation. A pending recap can finish after the source is deleted, and web/provider copies have separate lifecycles. Deleting on timestamp similarity could erase unrelated or edited notes. New source links, durable cancellation/tombstones, recovery and remote deletion receipts need an integrated implementation and tests before claiming full erasure.
3. **Review gaps in the prior patch:** `MeaningIndex` can re-cache a stale record if a new Find search begins after invalidation but before `MemoryStore.reload` finishes; the feature is hidden by the current shipping scope. The consent recheck occurs before an awaited database write, so revocation during that write is not proven to prevent a saved recap. Account refresh and sign-out also need a controlled concurrent-race test before their behavior can be certified. These are not represented as fixed.
4. **Physical iPhone:** a connected iPhone already has Doddy `com.bienos.doddy2.dev`, build 70. Merely testing that existing build would not validate these changes. Installing a same-identifier development build could replace the existing app, so this follow-up preserved it. Account switching and voice latency require an isolated signed test build and a person to exercise the microphone and account flow.

No deployment, server/agent configuration change, user-data deletion, live voice call or new provider request was performed by this follow-up. The completed pieces do not constitute a complete Phase 1, complete deletion or a verified account-isolation fix.

## Concrete boundary for the remaining implementation

- Resolve a stable authenticated account subject before opening account data; keep legacy installation data in a quarantined store until a person explicitly claims it. Never use an email address or expiring access token as the partition key.
- Scope the database, adjacent media, conversation/draft files, private-ID and sync settings, training data, caches, widgets, Spotlight, notifications and server-copy workers together. A visual account gate by itself is insufficient. Account changes need a generation boundary that rejects late results and stops or fences existing voice/sync/recap work. App intents and background launches must apply the same boundary.
- Move environment and repository ownership out of the process-wide immutable `AppEnvironment.shared` lifetime, or provide an equivalently complete switching mechanism. Do not destroy the old store when changing accounts. Verify that keychain restoration, fresh sign-in, sign-out, expired sessions, offline startup, device-only shortcuts and failed migration have explicit safe behavior.
- For newly created recaps, persist a stable source-conversation ID, derived-memory ID and deletion state; no timestamp matching. Use a durable tombstone and an idempotent cleanup process so work finishing after deletion cannot recreate a recap or remote copy. Preserve historical unlinked notes until the person makes an informed choice. Remote/provider deletion and backup retention need their own truthful acknowledgements.
- Before enabling the changes, test account A → sign out → B → A, interrupted transitions, pending model/database/network work, widget/Siri/Spotlight reads, legacy quarantine/claim, disk errors, source deletion during generation and during commit, and remote PUT/DELETE races. Add real-device tests only with an isolated signed build and test accounts.
