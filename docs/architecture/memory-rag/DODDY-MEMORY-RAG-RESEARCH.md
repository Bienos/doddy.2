# DODDY memory: architecture research

Researched 10 November 2026. Recommendations below are engineering judgments for the [audited repository](DODDY-MEMORY-RAG-AUDIT.md), not reproduced vendor benchmark claims. No new runtime dependency is recommended for Phase 1. API availability must be checked against the deployment target and installed SDK; DODDY targets iOS 17 with Swift 6 and GRDB 7.9.0.

## Recommendation

Choose **Option 1: existing structured stores + local FTS5 + selective, source-labelled context**. Fix scope, persistence and erasure races first. Retain the existing semantic Find experiment. Promote semantic retrieval to conversation only if a representative EN/PL evaluation demonstrates incremental recall without unacceptable false memories, device latency or battery cost. “RAG” is already present when retrieved notes are given to Claude; another vector database is unnecessary for that behavior.

## Technology comparison for this codebase

| Candidate | Accuracy / integration | Speed, cost, privacy, reliability | Compatibility, complexity, battery and scale | Decision |
|---|---|---|---|---|
| Structured SQL/profile lookup | Exact approved key/value; strong provenance, cannot infer arbitrary paraphrases | Local; no per-lookup API charge; survives offline | Already present; indexed lookups cheap; thousands of rows practical | Reuse profile and learned-fact tables |
| SQLite FTS5 / BM25 | Good names, IDs, keywords; current bilingual rules extend it; not semantic equivalence | Local and offline; fallback scan cost needs measurement | Ships in current GRDB store; no new SDK; preserve triggers and deletion compaction | MVP retrieval base |
| Existing Apple contextual embeddings | Can recover paraphrases; mean pooling and threshold need calibration for sentence retrieval | Note text stays on device; assets may need download; initial inference/cache build costs | `NLContextualEmbedding` available from iOS 17; support/model identity must be checked; all-pairs scan O(Nd), cache RAM O(Nd) | Keep Find; evaluate before voice |
| Foundation Models extraction | Useful for structured candidate proposals or summaries; generated text is not truth | `SystemLanguageModel` on device; no inference API bill; availability and compute constraints | Framework starts at iOS 26; eligible device, assets and locale gates; iOS 27 APIs must not leak into iOS 17 fallback | Existing opt-in recaps only; optional later proposer |
| Core Spotlight | System discovery and launching a note, rather than canonical fact lifecycle | Local system-managed index; app must delete identifiers and omit private content | Existing Spotlight integration can be reused; no new primary persistence; ranking/control differ from assistant requirements | Discovery surface, not memory authority |
| Custom Core ML sentence encoder | Potential multilingual quality with a retrieval-trained model | Offline after download; model size, CPU/GPU/ANE and thermal costs | Evaluate model license, quantization, minimum OS/operators, revision and Polish quality on device | Later experiment only |
| OpenAI embeddings + hosted retrieval | Multilingual model candidates; cloud hybrid retrieval supported | Sends text/query to an external processor; network, usage and storage cost; offline failure | A backend/consent/deletion dependency; already-used voice provider does not imply consent to embeddings | No silent upload; not MVP default |
| Mem0 | Extraction/update/retrieval and optional graph ideas | Usually additional extraction/model/store work; benchmark setup differs from DODDY | Replaces/duplicates significant existing consent and storage logic | Borrow candidate/consolidation ideas, no SDK now |
| Letta / MemGPT | Bounded always-visible blocks plus retrievable archives | Agent memory tools can add model steps; cloud/self-host operations | Useful conceptual separation; agent-editable memory needs DODDY typed approval gates | Borrow tiers, keep Swift core |
| Zep / Graphiti | Temporal graph helps entity relationships and historical validity | Ingestion/consolidation and operations beyond simple local lookup | Adds schema, indexing and privacy complexity; graph scaling is not DODDY's demonstrated bottleneck | Defer until temporal/project evidence justifies |
| LangChain / LlamaIndex | Retrieval composition, fusion and evaluation patterns | Runtime/tool orchestration can add steps and infrastructure | Python/TS services do not solve the iOS source-of-truth or account isolation problems | Use patterns, no framework dependency |

SQLite FTS5 supplies Unicode tokenization and BM25 ranking; its documentation also describes external-content synchronization and secure deletion caveats. Those capabilities fit DODDY's existing `memories_fts` triggers. A BM25 score is neither calibrated confidence nor factual correctness. [SQLite FTS5](https://www.sqlite.org/fts5.html)

GRDB 7.9.0 documents async database access and transactional migrations. Keep the pinned version and the single `DoddyDatabase`; adding a separate SwiftData, Core Data or vector store would introduce another deletion and migration boundary without demonstrated benefit. [GRDB 7.9.0](https://github.com/groue/GRDB.swift/tree/v7.9.0)

Apple's multilingual contextual models organize support by script and language. A shared model space makes cross-language experimentation reasonable, but DODDY's average of token vectors is not a measured guarantee of EN/PL sentence retrieval quality. Store/check model identifier, revision and dimension before mixing vectors. Asset availability and download are distinct from local inference. [Apple WWDC23 multilingual models](https://developer.apple.com/videos/play/wwdc2023/10042/), [NLContextualEmbedding](https://developer.apple.com/documentation/naturallanguage/nlcontextualembedding)

The current Foundation Models documentation distinguishes the on-device system model from newer provider/cloud capabilities. Availability depends on device and model readiness; call `supportsLocale` for the requested language and retain the existing no-model path. Do not promise Polish based only on the phone UI language or general Apple Intelligence marketing. Guided output constrains shape, not factual grounding. [Foundation Models](https://developer.apple.com/documentation/foundationmodels), [SystemLanguageModel](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel), [locale support](https://developer.apple.com/documentation/foundationmodels/supporting-languages-and-locales-with-foundation-models)

Core Spotlight exposes app content to system search; it does not replace the authoritative memory record, user approval, provenance or erasure rules. Its identifiers must follow the same privacy/deletion lifecycle. [Core Spotlight](https://developer.apple.com/documentation/corespotlight) The documentation landing page required JavaScript in this research environment; detailed behavior should be checked in the installed SDK before any new adoption.

OpenAI documents `text-embedding-3-small` and `text-embedding-3-large`, configurable dimensions, and hosted retrieval with text/embedding rank fusion. They are candidates for an explicitly consented cloud experiment, not required infrastructure. No embedding call was made. Raw Float32 storage at 1,536 dimensions costs `10,000 × 1,536 × 4 = 61,440,000` bytes (58.6 MiB), excluding text and index overhead; a 512-dimensional experiment would be 19.5 MiB. These are arithmetic estimates, not measured DODDY storage. [Embeddings](https://developers.openai.com/api/docs/guides/embeddings), [Retrieval](https://developers.openai.com/api/docs/guides/retrieval)

## Memory research: useful lessons and limits

* **MemGPT (2023):** separates small in-context memory from larger retrievable archives. For DODDY, approved style/profile belongs in a bounded context block; episodic detail belongs in queryable sources. This does not require adopting its agent runtime. [Paper](https://arxiv.org/abs/2310.08560)
* **Letta:** persistent memory blocks are always present when attached; archive retrieval is separate. Blocks are editable by default, which conflicts with DODDY's rule that model text alone cannot confirm durable personal facts. Prefer read-only approved facts and typed proposals. [Memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks), [stateful agents](https://docs.letta.com/v1-sdk/concepts/stateful-agents)
* **Mem0 (2025):** studies selective extraction/consolidation and graph variants. Its reported token/latency gains compare specific LoCoMo configurations; they do not predict DODDY's voice latency, Polish accuracy or consent behavior. Learn from bounded extraction rather than importing its headline percentages. [Paper](https://arxiv.org/abs/2504.19413)
* **Zep (2025):** treats temporal relationships and changes as first-class data. Adopt observed/valid timestamps and explicit supersession when needed. A temporal graph is not necessary to fix current local retrieval. Vendor evaluations are not directly comparable to a phone fixture. [Paper](https://arxiv.org/abs/2501.13956)
* **LongMemEval:** evaluates extraction, multi-session and temporal reasoning, updates and abstention. Use that task breakdown for DODDY's tests; retrieval recall alone misses false certainty and outdated facts. The published benchmark is not an executed DODDY result. [Paper](https://arxiv.org/abs/2410.10813)
* **MemoryTax (21 October 2026):** a recent small empirical study cautions that selective writers can discard facts stronger readers later need. Its abstract explicitly limits the experiment to one conversation and one run per cell, with asymmetric photo evidence. It motivates provenance and selective source retention, not storing every personal disclosure or declaring any system universally superior. [Paper](https://arxiv.org/abs/2610.29823)
* **Context engineering:** a small relevant context and just-in-time retrieval can be better than filling the window. Cache stable rules, keep identifiers to fetch sources when necessary, and compact with explicit uncertainty. [Anthropic engineering guidance](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

Hybrid retrieval can union lexical and semantic candidates and apply reciprocal-rank fusion instead of combining incomparable raw cosine/BM25 scores. Reapply owner, privacy, status and expiry filters first. DODDY can implement a small native ranker if evaluation supports it; it need not deploy a framework. [LlamaIndex reciprocal fusion](https://developers.llamaindex.ai/python/framework/integrations/retrievers/reciprocal_rerank_fusion/), [LangChain retrieval](https://docs.langchain.com/oss/python/deepagents/retrieval)

## Three practical alternatives

All latency figures here are **targets/engineering estimates**, not measurements. Effort assumes one engineer familiar with DODDY; account migration and product review can dominate.

| Criterion | Option 1: reliable local MVP | Option 2: intelligent hybrid | Option 3: advanced personal memory |
|---|---|---|---|
| Features | Existing approved profile/facts, FTS, source-labelled recaps, selective excerpts, deletion | Option 1 + calibrated EN/PL semantic fallback, metadata ranking, query-sensitive learned context | Option 2 + temporal/project graph, consolidation, consented cross-device archives |
| Complexity | Small repairs now; 2–4 engineer-weeks for remaining isolation/lifecycle work | Additional 3–6 weeks including device evaluation | Several months; uncertainty high |
| Latency | Local retrieval p95 target ≤50 ms on supported phones at 5k notes; skip unnecessary search | Warm hybrid target ≤100 ms; cold embedding index built outside voice | Variable 0.2–2+ s multi-step retrieval; explicit progress state |
| Cost | Zero added model calls, embedding fees or hosting from this patch; normal prompt tokens remain | Local inference no API fee; battery, storage and optional extraction costs | More model calls, synchronization and infrastructure; budget caps necessary |
| Privacy | Existing local records; fix owner isolation; consent for selected cloud context | Device embeddings preferred; same erasure/ownership gates | More copies/processors; more complex export and deletion |
| Reliability | Offline recall; lexical misses and bounded history | Missing model assets, unsupported locale, stale vector version; fall back to lexical | Ingestion/sync/graph failures, eventual deletion, conflict resolution |
| Dependencies | None new | Possibly one evaluated Core ML model, not necessarily ANN | Backend services, authenticated sync, job processing if justified |
| Maintenance | Existing Swift/GRDB conventions | Model/version evaluation and cache lifecycle | Highest operational and privacy burden |
| MVP fit | **Recommended** | Conditional on measured improvement | Not justified for launch |

## Extraction, background work and caching

Explicit Save and reviewed preference updates can run during a conversation, with read-back before success. Rule candidates should reuse existing SaveSuggestions after the session. Model extraction should run after a session or during idle foreground time, only with appropriate consent, bounded input, a cancellable job and revalidation before save. Scheduled background work is a best-effort supplement, never the only route to persistence. Apple's scheduler chooses when to run refresh/processing work; an unstructured Swift `Task` is not a background execution entitlement. [Apple background strategies](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app)

Context caching reduces repeated prefix work, not the need to retrieve fresh facts or apply consent. Put stable policy/tool definitions before variable personal context where the provider supports it; measure cache hits rather than assuming savings. [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)

## European privacy requirements translated into engineering

GDPR principles include purpose limitation, minimization, accuracy and retention limits; rights include access, correction and qualified erasure, with privacy by design and appropriate security. Sensitive categories and international transfers need separate analysis. Product switches alone do not establish a lawful basis, processor agreement, compliant transfer mechanism or fulfilled erasure request. The implementation must inventory records and derived indexes/copies, bind data to an owner and provide accurate deletion receipts. Formal launch legal review remains outstanding. [GDPR official text](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX%3A32016R0679)

## Promotion gate for semantic retrieval

Use an owner-approved synthetic/redacted bilingual corpus with exact IDs, paraphrases, temporal updates, malicious instructions and unanswerable questions. Compare the same questions against lexical, semantic and fused candidates. Report Recall@5, Precision@5, answer correctness, false-memory/abstention rate, p50/p95 cold and warm latency, first audio, token cost, bytes, peak RAM and energy. A suggested gate is ≥10 percentage-point recall gain on paraphrases with no regression on IDs/deletions/authorization, no increase in false memories, and the device latency budget met. These are proposed acceptance thresholds, not experimental results. ANN becomes a candidate only if brute-force vector search demonstrably misses the resource budget.
