## Code
- **Default branch:** `main`. It is the only permanent branch; every change arrives by pull request. Agents squash-merge their own pull requests once `core`, `ios-build` and `sensitive-paths` are green (`AGENTS.md`, "Merging"). `sensitive-paths` runs its guard script from `main`, never from the pull request, and also covers lockfiles, CI scripts, agent settings and skills, `site/api/` and `server/voice-token/` (#408); tying the three checks to GitHub Actions in the live ruleset is owner queue 62.
- **CI:** `.github/workflows/ios.yml`. Pushes to `main` run every job, including the whole UI suite (ADR-765, ADR-811); pull requests run path-selected jobs and only the UI smoke classes. ## What changed in the product since 7 Nov (from `main`, not on a device)

The welcome signs in with **Apple or Google**; email codes are hidden (`2026-11-09-email-sign-in-off-for-now`). Doddy Web: Apple or Google opens the same account as the iPhone, in a small window on a computer (#374). Your Doddy account is under Settings › About. Linking an iPhone's earlier data takes a one-time code the iPhone asks for itself (#383; an app build from before it can't link). - **Tokens and devices** (approved by the owner on 14 Nov: `2026-11-12-account-and-device-tokens`, `2026-11-12-one-token-per-server`, `2026-11-12-voice-token-fair-share`; signed taps are not being built, App Attest is for later). **`doddy` (live since the 19:38 UTC deploy of 14 Nov):** one signing key per purpose, with a key id and an optional previous key for rotation (#480; `DODDY_IDENTIFIER_KEY` keeps each iPhone's user id where it is; steps in `docs/integrations/DEPLOY_RENDER.md`); each iPhone that signs in with its device id is stored, an account's iPhones are listed and one can be revoked (`GET /v1/web/devices`, `DELETE /v1/web/devices/:id`; a join to another account ends after 90 days, `DODDY_DEVICE_JOIN_DAYS`, unless the iPhone signs in again; #485); `POST /v1/session/account` trades a Doddy account's token for a 30-day session of the backend's own, which a revoke or the account's deletion ends (#486); `account-session`, the voice server's own session for a Doddy account (#481). **`doddy-messaging` (live since 14 Nov 18:55 UTC):** a Doddy account's device token stops working after 60 days unseen or 180 days after it was issued, and `POST /v1/accounts/sign-in` with the current token returns a fresh one (#476, migration 040; ## Known problems
- **Security review, 12 Nov 2026** (read-only, not a penetration test; an artifact in the owner's account). Fixed in code since: deleting an account reports success only when each server confirmed (#391, #409), and it deletes the account's voice conversations (#425, #426, #445). Still open: old Supabase functions without sign-in run in the accounts project, one of them an open OpenAI proxy; the old Render copies above still run; notes stay on a shared iPhone after a sign-out, visible to whoever signs in next (nothing is sent to their account since #390; the erase button is built, #454, and not recorded on a device); the shared hourly voice limit (100 for everyone) can be used up by a few accounts, though since #478 an account that already had 10 waits once half of it is used (owner queue 56 is decided). The console steps are the owner's.
- **Google sign-in fails** with `redirect_uri_mismatch` until Supabase's callback is registered on the Google OAuth client (owner queue 25). Apple on the website needs owner queue 28.
