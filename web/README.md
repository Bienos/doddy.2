# Doddy Web

The browser workspace for the same Doddy account the iPhone uses (ADR-585, ADR-586). Built to `web/dist` and served by `backend/` on the same origin, so the session is an HttpOnly cookie and there is no CORS.

- How it works, how to run, test, deploy and roll back: `docs/platforms/web.md`.
- Why it is built this way and what comes next: `docs/architecture/WEB_AND_SHARED_PLATFORM.md`.
- Colours (the website's palette, `CandidateTokens.swift`), metrics, wordmark, Doddy's poses and the favicon are generated by `tools/gen_web_assets.py`; don't edit `src/styles/tokens.css` or `public/brand/` by hand. The look is the website's (ADR-594): `src/styles/app.css`, and `logbook.css` for Logbook.
- Logbook (ADR-593): `src/pages/LogbookPage.tsx` and `src/logbook/`; reads `GET /v1/web/logbook`; the iPhone can't send days yet (`IPHONE_SENDS_LOGBOOK` in `src/logbook/config.ts`), so it shows "Logbook is off" and an example on request. `LOGBOOK_ENABLED` hides the page.
- Memory and Ask Doddy (ADR-595): `src/pages/MemoryPage.tsx`, `AskPage.tsx` and `src/memory/`; the iPhone's sending is written but not compiled or run on a device, so `IPHONE_SYNCS_MEMORY` in `src/memory/config.ts` stays false: the pages open on "nothing is kept" and the menu says Soon. `MEMORY_ENABLED` hides them.
- Every visible word is in `src/i18n/messages.ts` and, for Logbook, `src/i18n/logbookMessages.ts` and `memoryMessages.ts` (Polish default, English).

```sh
npm ci
npm run typecheck && npm test   # unit tests against contracts/ fixtures
npm run build                   # web/dist
npm run e2e                     # needs backend/ built: real server + Chromium
```
